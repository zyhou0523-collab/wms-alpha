# WMS 后续 SaaS 化迁移注意事项

## 一、迁移背景

当前 WMS 是独立 PC 系统，已经具备入库、出库、库存、报表、系统管理和演示数据闭环。后续计划迁移到新的供应链 SaaS 平台，成为平台内的 WMS 业务模块。本文件用于提醒后续产品、架构、开发、测试和实施团队：平台化迁移不是简单搬代码，而是要处理租户、权限、主数据、接口、部署和运维体系的边界。

## 二、迁移原则

1. 冻结独立版，平台化改造另起分支或模块，不直接污染独立版稳定基线。
2. WMS 业务能力优先迁移，系统管理、登录、权限、组织等能力优先复用平台能力。
3. 订单主状态、作业任务状态、接口状态、包装状态继续保持分离。
4. 保留历史兼容状态映射，不硬删除历史数据。
5. 先迁移可演示闭环，再逐步接入真实 SAP、MES、SRM、CRM、履约和追溯系统。
6. 所有跨系统接口必须补充幂等、重试、审计和失败补偿。

## 三、模块边界建议

| 能力 | 迁移建议 |
|---|---|
| 登录认证 | 迁移到平台统一 IAM/SSO |
| 用户角色菜单 | 复用平台权限中心，WMS 只声明菜单、按钮和权限点 |
| 部门/岗位 | 复用平台组织中心 |
| 产品主数据 | 优先由 MDM/PLM/ERP 维护，WMS 保存引用和必要快照 |
| 客户/供应商/货主 | 优先由 CRM/SRM/主数据中心维护 |
| 仓库/库区/库位 | 保留 WMS 模块维护，但需关联平台组织和租户 |
| 入库/出库/库存 | 作为 WMS 核心业务模块迁移 |
| 报表 | 可先保留 WMS 报表，后续接入平台 BI |
| 接口日志 | 接入平台统一集成中心和审计中心 |
| 操作日志 | 接入平台统一审计，但保留业务日志视图 |

## 四、多租户与数据权限

当前独立版主要通过仓库、货主、角色、用户授权实现数据范围控制。SaaS 化后需补充：

1. `tenant_id`：所有业务表、主数据表、日志表的租户隔离字段。
2. `org_id` 或平台组织字段：支持集团、事业部、公司、工厂等组织层级。
3. 仓库权限：按租户、组织、用户、角色维度授权。
4. 货主权限：适配 3PL、多货主、VMI 等场景。
5. 接口数据权限：外部系统回调必须带租户/组织/业务域上下文。
6. 报表数据权限：报表聚合时必须继承同样的数据范围。

## 五、数据库迁移重点

| 领域 | 迁移动作 |
|---|---|
| 表结构 | 增加租户、组织、创建人、更新人、删除标识、版本号等平台统一字段 |
| 主键 | 评估自增 ID 是否改为平台分布式 ID |
| 编码规则 | 发运订单、入库单、收货批次、发货单、盘点单等接入平台编码服务 |
| 字典 | 字典类型迁移到平台字典中心，保留 WMS 字典命名空间 |
| 状态 | 建立状态映射表，兼容历史状态与新状态 |
| 日志 | 接入平台统一审计日志，保留业务单据维度查询 |
| Seed | demo seed 与生产初始化脚本拆分 |
| 数据清洗 | 平台化前先清理 mock-only 数据、重复数据和历史异常状态 |

## 六、接口迁移重点

1. 登录、菜单、用户、角色接口应迁移到平台能力。
2. WMS 业务接口保留 `/api/wms` 或平台统一模块前缀。
3. SAP/MES/Fulfillment/Trace/CRM mock 接口需替换为平台集成中心或真实连接器。
4. 所有写接口补充幂等键、操作人、来源系统、请求 ID。
5. 所有失败回传写入接口日志，不污染订单主状态。
6. 对外接口需要 OpenAPI 契约和回归测试。
7. 批量操作接口需要返回成功数、失败数、失败原因明细。

## 七、前端迁移重点

| 当前能力 | SaaS 化建议 |
|---|---|
| 独立登录页 | 替换为平台登录态和统一路由守卫 |
| MainLayout | 接入平台外壳、导航、面包屑、用户中心 |
| 菜单 | 使用平台菜单注册或远程菜单 |
| 多语种 | 接入平台 i18n 资源管理 |
| 权限按钮 | 接入平台权限指令或权限组件 |
| 仓库选择器 | 与平台组织/仓库上下文联动 |
| mock 数据 | 保留为开发 fixture，不进入生产构建 |
| 报表 | 评估迁移到平台 BI 或统一报表引擎 |

## 八、业务流程迁移重点

### 入库

- 明确预期到货通知单关闭流程是否为正式流程。
- 明确入库 SAP 回传按订单汇总还是按收货批次展示。
- SN 采集、收货、取消收货、关闭、重传 SAP 需补充状态机测试。
- 包装绑定 `BOUND` 不建议作为订单主状态。

### 出库

- 发运订单主状态保持简洁，分配、拣货、复核、发货任务状态分层维护。
- 部分发运关闭生成分单和完全发运普通关闭规则需保留。
- 出库 SAP 回传建议保持订单关闭后触发。
- 分配失败、SAP 失败、追溯失败不进入订单主状态。

### 库存

- 库存余额、SN 状态、库存流水必须保持强一致。
- 分配、拣货、发货、取消操作要有补偿策略。
- 盘点调整和库存移动必须纳入审计。

## 九、测试与质量建议

1. 建立接口契约测试，覆盖入库、出库、库存、系统管理核心接口。
2. 建立端到端测试，覆盖入库闭环、出库闭环、库存移动、盘点、SAP 重传。
3. 建立数据迁移测试，覆盖历史状态、历史 demo 数据、兼容字段。
4. 建立权限测试，覆盖仓库、货主、角色、菜单、按钮。
5. 建立性能基线，重点测试库存查询、SN 查询、单据列表和报表。
6. 建立发布回滚方案，平台化初期保留独立版回退路径。

## 十、建议迁移阶段

| 阶段 | 目标 | 产出 |
|---|---|---|
| 阶段 1 | 冻结独立版 | 稳定分支、tag、冻结文档 |
| 阶段 2 | 平台适配设计 | 模块边界、权限模型、数据模型、接口契约 |
| 阶段 3 | 前端壳迁移 | 路由、菜单、登录态、权限按钮、多语种 |
| 阶段 4 | 后端服务迁移 | API 前缀、租户字段、平台 IAM、审计日志 |
| 阶段 5 | 数据迁移 | schema 改造、状态映射、历史数据清洗 |
| 阶段 6 | 集成联调 | SAP/MES/SRM/CRM/履约/追溯 |
| 阶段 7 | 回归验收 | 自动化测试、UAT、性能、安全检查 |

## 十一、高风险事项

1. 租户隔离不足导致跨客户数据泄露。
2. 平台权限与 WMS 仓库/货主权限模型冲突。
3. 真实 SAP/MES 接口粒度与当前 mock 粒度不一致。
4. 库存余额与 SN 状态在取消、回退、重传场景下不一致。
5. 历史兼容状态硬删除导致旧单据不可查。
6. 把接口失败状态写入订单主状态导致流程失真。
7. 前端 mock 数据误进入生产构建。

## 十二、迁移前检查清单

- [ ] 冻结分支和 tag 已创建。
- [ ] 独立版前端可访问。
- [ ] 后端在 JDK/Maven 环境完成构建和测试。
- [ ] SQL 初始化脚本可从空库执行。
- [ ] 默认 demo 数据覆盖入库、出库、库存、系统管理主场景。
- [ ] 状态字典、按钮规则、SAP 状态已文档化。
- [ ] 已识别需要平台接管的系统能力。
- [ ] 已确定租户、组织、仓库、货主权限模型。
- [ ] 已制定真实外部系统接口替换计划。
